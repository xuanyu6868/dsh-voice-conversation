# v2.0 更新与实机验收

本版变更了输入语义与会话归属；不要只替换一段旧代码。先备份当前运行插件，再整体更新本仓库受版本控制的插件文件。

## 给 DeepSeek Harness 的完整提示词

复制下面内容：

```text
请把我的语音对话插件更新为以下仓库 main 中的 v2.0.0：
https://github.com/xuanyu6868/dsh-voice-conversation

先读取 README.md、HANDOFF.md、docs/UPGRADE-v2.md，确认拉取的是最新代码。

1. 找出当前实际安装并运行的 @local/voice-conversation 插件目录与 profile。已知原工作目录曾为 ~/Documents/deepseek-harness/default-workspace/voice-conversation/，但必须核对真实链接/安装位置，不能只改一个未被使用的副本。
2. 备份当前插件源码、cordis.patch.yml 与必要运行配置。禁用旧插件，确认它的录音、播放与发送计时器已清理；不关闭或卸载其他插件。
3. 在临时 Git 工作副本中拉取本仓库，运行 npm ci、npm run check、npm test；测试依赖仅用于开发，不需要复制 node_modules 到插件目录。记录版本/commit 和结果。
4. 更新 client.js、impl.mjs、package.json 及随附文档等对应文件；保留我的实际 cordis 配置及云端凭据，按差异合并，不直接覆盖掉本机定制配置。host.mjs 是稳定引导，本版没有改动它。
5. 继续使用我当前已配置的 ASR 和 TTS、音色、语速、麦克风。不要因为历史文档提到 SenseVoice/GPT-SoVITS，就重新安装、下载或切回那些本地模型；不要更换模型、改凭据或重建语音后端。已有 Edge 桥接能用就不重装。
6. 启用插件，使 Host 和 Client 都载入新版本。仅重载 Host 不能证明 client.js 缓存已刷新；必要时重新加载客户端或重启应用。打开语音设置→高级，确认实际页面显示“插件版本：2.0.0”。
7. 验收以下实际行为：
   - 在语音页点击“键盘”：录音暂停但会话保留。输入文字不自动发送；Enter/发送按钮才提交，Shift+Enter 换行，中文候选确认不误发。
   - 普通聊天输入框的既有草稿不被读写或自动提交。语音页转写有自己的确认区，可以取消、清除、编辑。
   - 完整页有效语音识别后等待 1.5 秒发送；最小化取消倒计时，后续转写保留到语音页确认；展开不暗中恢复自动发送。已有朗读最小化/展开不中断。
   - 静音和无声环境不应因“。”“…”等纯符号触发助手；“好”“对”等正常短回答仍有效。保留日志，必要时记录音频条件。
   - A、B 两个已有会话各自预先说一个不同事实，再分别开启语音询问：回答必须继承各自历史。快速切换时旧录音/识别/回复/朗读不能进入新会话；普通聊天原草稿、语音键盘草稿分别保留。
   - 语音页可读到该会话历史，回答的段落、加粗、列表、代码格式正常，滚动阅读不会被强制拉回底部。
   - 连续使用、快速切换、长回复和最小化后检查原先十余秒全局卡顿；收集出现时间与 voice-flow.log 中 ui.long-task 以及 client-errors.log 相应片段。不要把全部 UI 等待都认作模型慢，也不要没有性能证据就宣布彻底修复。
   - 结束语音后确认麦克风释放；不要通过在多个会话同时录音实现跨会话。
8. 自动测试、界面目测、真实录音/模型对话和性能验证分开汇报。无法实际操作的项目标为待验证，不用“注册成功”“代码包含”代替验收。

不要实现或接入 dsh-memory，本轮只更新语音助手；长期记忆系统后续另行讨论。不要把录音、真实聊天、密钥、令牌或本机日志推到 GitHub。
```

## 手动回退

出现阻塞性回归时，禁用 v2，恢复升级前备份的整套插件源码与清单，重新加载 Host 和 Client，确认旧版行为恢复。不要只把版本号改回去，不必卸载识别模型或删除云端凭据。

## 范围说明

本版复用原生 Session 上下文，不提供跨会话自动共享记忆；这是为防串话保留的边界。UI 演示文件 `voice-preview.html` 无录音/模型请求，并非实机截图。自动测试通过不代表本机 ASR、音频、权限或布局已验证。
