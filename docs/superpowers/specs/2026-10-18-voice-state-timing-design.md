# 语音对话状态与时序修复设计

日期：2026-10-18  
状态：待用户审阅  
范围：方案 A（保守热路径），只修客户端状态、取消语义和竞态防护

## 1. 背景与已核对事实

当前语音链路已经跑通：SenseVoice 本地识别、识别后 1.5 秒自动发送、LLM 回复、Edge/系统语音朗读、朗读后自动继续聆听。Edge TTS 已有一句预取：第 N 句播放时第 N+1 句可提前请求，`stopSpeaking()` 会取消预取。

本设计只处理 `client.js` 中的状态与时序问题，不修改 ASR/TTS 引擎、`host.mjs`、Edge 服务、VAD 参数或跨会话架构。

已核对的代码事实：

- `sendPending` 只是布尔值；倒计时回调在 1.5 秒后调用 `submit()`，提交前不重新确认输入框仍处于可提交状态，也不确认草稿仍与倒计时启动时一致。
- `cancelPendingSend()` 只清除 `sendPending`，不区分“用户取消”“用户编辑”“用户已手动发送”。
- 识别异步回调只检查 `phase === 'transcribing'`；旧会话或旧轮次晚到时，没有会话代次或轮次代次防护。
- `voice.error` 是单一错误字段；一个环节成功可能清掉另一个环节仍有意义的错误提示。
- 错误重试目前只在 `phase === 'error'` 时显示，动作是重开语音会话；识别失败和合成失败没有分环节恢复动作。
- Edge 在启动日志和设置页部分位置被归为“系统语音”，与实际云端路径不一致。
- “没反应”误识别不能直接定性为模型问题；未来如要处理，需先确认送入识别器的音频没有截断。本批不改 VAD，因此不做该结论。

## 2. 目标

- 自动发送不误发、不重复发。
- 用户取消、编辑、清空或手动发送时，有明确且互不相同的状态语义。
- 旧会话、旧轮次、旧定时器、旧合成结果不能写入当前草稿、提交当前输入或开始播放。
- 识别、麦克风、草稿写入、合成分别报告和恢复。
- 保持现有正常链路速度，不增加识别或合成前的等待，不引入朗读期间常驻录音。

## 3. 非目标

- 不调整 VAD 阈值、停顿时间、自动发送延迟或单段录音上限。
- 不更换 SenseVoice、Edge TTS、系统语音或 MiniMax。
- 不做真正的语音插话或朗读期间持续采集。
- 不改跨会话朗读的宿主架构。
- 不重构整个客户端，不引入大型测试框架。

## 4. 自动发送状态设计

引入“待发送记录”，替代仅靠布尔值判断：

- `sendId`：每次进入待发送状态递增，旧定时器凭旧 id 不能提交。
- `sendDraft`：启动倒计时时的完整草稿快照。
- `sessionGen` 与 `turnId`：确认定时器仍属于当前语音会话和当前识别轮次。

### 4.1 启动倒计时

识别文字成功写入输入框后：

1. 生成新的 `sendId`。
2. 保存当前完整草稿为 `sendDraft`。
3. 设置 `sendPending = true`，进入等待发送状态。
4. 启动 1.5 秒定时器。

### 4.2 定时器触发

定时器触发时先原子地认领本次发送：只有当前 `sendId` 与定时器携带的 id 相同，才把这次发送标记为已消费；随后继续校验：

- 语音会话仍处于当前 `sessionGen`。
- 当前轮次仍是启动倒计时时的 `turnId`。
- 语音会话仍绑定同一个 `owner`。
- 输入框仍处于可提交状态。
- 当前草稿与 `sendDraft` 完全一致。

任一校验失败，只记录跳过原因，不调用 `submit()`。全部通过才提交一次，并进入等待回复状态。

### 4.3 用户点击“取消自动发送”

语义定义为“暂停自动发送，保留文字等待用户编辑”，不是立即恢复聆听：

- 取消定时器并使 `sendId` 失效。
- 保留草稿。
- 进入明确的 `editing` 状态，不启动新录音，避免新识别覆盖正在编辑的内容。
- 状态文案显示“已暂停自动发送”。
- 提供明确的“继续聆听”动作，供用户编辑后主动恢复免手动循环。

### 4.4 用户编辑或清空草稿

只要待发送期间草稿与 `sendDraft` 不再一致：

- 取消定时器并使 `sendId` 失效。
- 保留用户当前内容，包括空草稿。
- 进入 `editing` 状态。
- 不自动开始新录音。

### 4.5 用户手动发送

输入框从可提交状态转为提交中，或检测到提交动作时：

- 取消旧定时器并使 `sendId` 失效。
- 进入等待回复状态。
- 不恢复聆听，直到回复朗读完成或用户明确继续。

## 5. 会话与轮次防护

增加两层代次：

- `sessionGen`：开始或结束语音会话时递增，用于拦截旧会话回调。
- `turnId`：每一轮录音、识别、提交递增，用于拦截同一会话中的旧轮次回调。

检查点不只在异步任务开始时：

- 麦克风权限返回后、attaching stream 前检查。
- 录音停止后、解码音频前检查。
- 音频转换完成后、发起识别请求前检查。
- 识别请求返回后检查。
- 真正调用 `setDraft()` / `insertText()` 前再次检查。
- 写入草稿后、更新字幕和状态前检查。
- 自动发送定时器真正调用 `submit()` 前检查。
- 合成结果准备开始播放前检查；现有 `playbackGen` 保留，预取结果也必须匹配当前播放代次。

过期结果只记录日志，不改变当前会话状态。

## 6. 分环节错误与恢复

将单一 `voice.error` 改为分环节错误，至少区分：

- `mic`：麦克风权限或设备错误。
- `asr`：识别失败。
- `draft`：识别文字无法写入草稿。
- `synth`：合成或播放失败。

成功只清除对应环节的错误，不用一个环节的成功覆盖另一个环节的故障。

### 6.1 麦克风权限或设备失败

- 进入可恢复的错误状态，说明需要检查权限或输入设备。
- “重试”只重新请求麦克风，不重建聊天、不重发消息。
- 浏览器仍拒绝权限时保持错误状态和提示。

### 6.2 识别失败

- 不重新发送用户问题。
- 默认恢复到可重新说话的状态，并保留识别错误提示。
- 若自动恢复也失败，提供“重试识别/重新聆听”入口。

### 6.3 草稿写入失败

- 不清空识别结果，不调用提交。
- 提示输入框有未处理内容。
- 由用户处理草稿后明确继续。

### 6.4 合成或播放失败

- 保存最近一次待朗读文本及来源。
- “重试朗读”只对已有回复重新合成，不重新发送问题，不重新执行工具。
- 播放成功只清除 `synth` 错误。

## 7. 引擎标识与日志

统一从当前 `voiceURI` 得出引擎信息：

- `edge:*` 显示为“云端 Edge TTS”。
- 系统语音显示为“本地系统语音”。
- 保留的 GPT-SoVITS 路径显示为“本地 GPT-SoVITS”。
- MiniMax 显示为“云端 MiniMax”。

启动日志、设置页和错误日志使用同一判断，避免 Edge 被写成系统语音。只做标签修正，不新增状态轮询或预热请求。

## 8. 轻量自动验证

不搭建大型测试框架，只增加可控的 Node 测试脚本。通过测试专用句柄调用小组状态函数，不扩大生产环境 API。

必须覆盖：

1. 倒计时已启动后，模拟手动提交；旧定时器稍后触发，最终 `submit()` 只发生一次。
2. 待发送期间编辑或清空草稿；旧定时器触发时不得提交。
3. 点击取消自动发送后进入 `editing`，草稿保留，录音不自动开始。
4. 结束旧语音会话并开启新会话后，旧识别回调返回，不得写入新 owner 的草稿。
5. 同一会话中旧 `turnId` 的识别回调返回，不得覆盖当前轮次。
6. 合成失败后调用重试，只触发朗读路径，不调用 `submit()`。

## 9. 实测与性能验收

验收条件按“相同输入、相同操作”比较，不笼统承诺所有场景请求数量绝对不变：

- 正常链路在现有一句预取之外，不新增识别或合成请求。
- 取消、停止或结束会话时，预取请求必须取消，过期结果不得播放。
- 用户主动重试产生的额外请求属于预期行为，单独记录。
- 不出现重复提交、重复识别或旧结果触发的额外合成。
- 修改前后用 `voice-flow.log` 对比 `asr.request/result`、`synth.stream-start`、`play.start` 和发送关卡耗时；发现明确退化就回退相关改动。
- 深色模式和窄窗口只有实际查看后才能标记通过；当前环境未暴露可用的 `cua_repl` 工具时，不把该项标为已验收。
