## 环境（非敏感）

- macOS（Apple Silicon），DeepSeek Harness 桌面版，profile `desktop`
- 插件真实加载位置：profile 软链 → 工作区目录（已核对，非副本）
- ASR：`sensevoice-local`（SenseVoiceSmall ONNX int8 + Silero VAD，sherpa-onnx CPU 子进程，threads=2，maxPending=4），batch API，无原生流式
- TTS：云端 Edge TTS，经本机桥接 `edge-server.py`（127.0.0.1:9884，edge-tts==7.3.1）
- 代理：Clash 系统代理 + fake-ip DNS；Edge 域名必须走代理（本次采样时代理正常）
- 桥接与 ASR worker 采样前均为热（桥由 10:39 自检预热；首个 ASR 结果 20ms）——**本轮无冷启动样本**

## 复现步骤

插件重载一次后：同一短问句语音问答 ×3（"现在几点"类）→ 长回复 ×1（多句）→ 含工具调用问答 ×1（查询时间，web-search）。窗口内另有一次无声/噪声样本（`asr.discarded empty-or-symbols`，纯符号过滤工作正常）。

## 七个重点核查的结论

1. **是否必须等整条消息生成完才 TTS**：【代码确定】是。`acceptChatSnapshot` 只对终态 assistant 节点调 `speak()`（client.js:1331-1336）；流式 partial 只显示不朗读。首个完整句出现早于 reply.final 0.3–2.3s。
2. **splitSentences 合并拖慢第一声**：【代码确定 + 实测】短句按 ≤120 字合并（client.js:279-293）；S3 首块 120 字合成 3.31s，若按句切首句（约 22–40 字）实测合成约 2.6s。
3. **各层等待完整 MP3**：【代码确定】三层都整段：`edge-server.py` 收齐所有上游块才响应；`impl.mjs callEdge` `await res.arrayBuffer()` 收全量；客户端 `res.blob()` 收全量。`edgeFirstChunkMs`（约 2.0–2.2s）证明上游分块早已开始到达——三层缓冲白白多等 0.4–1.2s。
4. **朗读队列积压/声音落后页面**：【实测证实】存在。结果文字完整→出声固定晚 ≈ 整段合成时长（3.3s）。前置引导句与结果句串行朗读（本例中引导句恰逢工具间隙，体验尚可，但结构上声音必然落后页面一个合成周期）。
5. **冷启动/重试/播放失败**：【实测】本轮无（readyMs 0–2，零重试零错误）。冷启动未测到。
6. **一句预取命中**：【实测证实】全部命中，句间停顿 5ms。首句不受并发影响（预取与首句并行，桥为 ThreadingHTTPServer）。
7. **模型首段文字之前的时间归因**：【部分实测】收据→首段文字 3.63–4.97s，其中宿主预处理/记忆检索/模型 TTFT 的细分**宿主无日志，标缺失**；这是最大单段耗时，建议后续在宿主侧补证据，不归咎于语音链路。

## 观测点缺失说明

- 用户物理停止说话：由 `voice.endpoint − 700ms`（VAD 判停窗口）推导，非直接观测。
- 浏览器收到首个音频**字节**：Edge blob 路径无法观测；已埋 `synth.headers`（响应头到达 = 宿主合成完毕时刻）作为最近邻点。
- 桥上游首块时间：已埋 `x-edge-first-chunk-ms` 响应头 → impl `tts.done.edgeFirstChunkMs`。
- S1 的 `reply.first-sentence` 未触发（流式增量中未出现句末标点直到 final），标缺失。
- 宿主模型管线内部（预处理/记忆/TTFT）：无日志来源。

## 给 Codex 的建议（按预期收益排序）

1. **流式送 TTS**（client.js）：在 partial 流式文本中按句切分，完整句一出现即入合成队列（与模型剩余生成并行）；保留 reply.final 兜底。预计短回复第一声 7.8–9.5s → 约 5.5–7s。
2. **首块免合并**：splitSentences 对队列首个块按句号粒度切，不做 120 字合并（合并保留给后续块以减少请求数）。S3 类长回复首声再省 ~0.7s。
3. **Edge 流式化**（桥 + impl + client）：桥逐块写响应（ chunked ），impl 透传，client 按块解码播放（复用 playPcmStream 调度思路，改 mp3 块解码）。首声再省 ~0.4–1.2s。改动最大，建议最后做。
4. 模型段（3.6–5s）需宿主侧 TTFT 证据，超出本插件范围。
